# PLC 엔지니어를 위한 AAS · 온톨로지 한국어 스터디

배경지식 없이 시작하여, 장치 정보를 AAS로 구조화하고 PLC 정보와 RDF 그래프로 연결하는 설계를 스스로 설명하는 것이 목표입니다.

이 자료는 공식 사양의 전체 번역이 아니라 **공식 문서를 바탕으로 새로 작성한 한국어 해설과 가상 PLC 예제**입니다. 규범적 판단은 원문을 우선합니다.

## 1. 다섯 자료가 각각 해결하는 질문

| 공부할 항목 | 해결하는 질문 | 비유 |
|---|---|---|
| IDTA AAS Specifications | 무엇을 표준으로 맞춰야 하나? | 문서 양식·통신·파일 포장의 규칙 모음 |
| AAS Metamodel Part 1 | 장치 정보를 어떤 구조로 표현하나? | 표준 장치 정보의 설계도 |
| Eclipse BaSyx | 구조화한 정보를 어디에 저장하고 어떻게 서비스하나? | 표준을 구현한 서버와 개발 도구 |
| W3C OWL 2 | 장치·신호·프로그램의 개념과 관계는 무엇인가? | 의미를 정의하고 추론하는 언어 |
| W3C SHACL | 등록한 그래프가 요구 조건을 만족하나? | 그래프의 검사 규칙과 검사 보고서 |

그 전에 RDF·식별자·JSON·API의 최소 기초를 익힙니다.

### 4주 일정 예시

- **1주차:** 공통 기초와 IDTA 사양 지도. 식별자와 트리플을 설명할 수 있게 만들기.
- **2주차:** AAS JSON 작성과 BaSyx 흐름 이해. 모터 한 대의 정보를 조회하기.
- **3주차:** OWL 모델과 RDF 질의. 변수–채널–장치 관계를 표현하기.
- **4주차:** SHACL 오류 사례와 통합 과제. 승인 전후 데이터를 구분하기.

## 3. 모든 장에서 사용할 가상 사례

```text
PLC_A
  └─ StartCommand: 출력 변수
          └─ Channel_03: 출력 채널
                  └─ Contactor_K1: 접촉기
                          └─ Motor_01: 실제 모터
```

- 제조사: `Example Motors` — 가상의 제조사.
- 제품 모델: `EM-100` — 가상의 모델.
- 설치 모터: `Motor_01`, 시리얼 `SN-DEMO-001`.
- 정격 전류: `12.5 A` — 학습용 임의 값.
- 설치 자산 ID: `urn:example:asset:motor-01`.
- AAS ID: `urn:example:aas:motor-01`.
- RDF 개체 IRI: `https://example.org/plant/Motor_01`.

`example.org`와 `urn:example:`는 학습용입니다. 예제의 개념 ID는 실제 IDTA·ECLASS·IEC CDD 표준 ID가 아닙니다.

## 4. 학습할 때 계속 확인할 네 가지

1. **표현과 사실:** JSON이 유효하다고 실제 사양이 맞는 것은 아닙니다.
2. **의미와 검증:** OWL로 추론 가능한 것과 SHACL로 등록을 거절하는 것은 다릅니다.
3. **식별과 주소:** 장치 ID, 장치 모델, API URL, 의미 ID는 다릅니다.
4. **정적과 실시간:** 정격 전류와 지금 측정한 전류는 다릅니다.

## 5. 도구와 예제 상태

필수 도구 없이 문서를 읽고 수작업으로 문제를 풀 수 있습니다. 선택 실습에는 다음을 사용합니다.

| 실습 | 선택 도구 |
|---|---|
| AAS 구조 보기 | JSON 편집기, BaSyx AAS Web UI |
| 온톨로지 편집·추론 | Protégé와 호환 reasoner |
| RDF 파싱·SPARQL | Python + RDFLib |
| SHACL 실행 | Python + pySHACL |
| BaSyx 서버 | Docker Compose, 공식 Starter Kit |

명령과 코드는 학습용으로 제공합니다. 이 자료 작성 과정에서 로컬 서버 실행이나 Python 실습 실행은 하지 않았습니다. 설치할 때 버전 호환성과 각 실습의 기대 결과를 확인하십시오.

BaSyx의 `latest` 문서는 바뀔 수 있습니다. 이 자료는 **AAS 메타모델 v3.1을 읽는 기준**으로 작성했지만, BaSyx의 모든 배포판이 이를 동일하게 지원한다고 가정하지 않습니다.

## 6. 수료 체크

- AAS, OWL, SHACL, BaSyx를 한 문장씩 설명할 수 있다.
- 동일 모델의 모터 두 대를 서로 다른 자산으로 식별할 수 있다.
- `id`, `idShort`, `globalAssetId`, `semanticId`를 구분한다.
- RDF 트리플에서 주어·술어·목적어를 찾을 수 있다.
- OWL의 domain 선언이 입력 타입 검사가 아님을 설명한다.
- SHACL 검사 실패를 근거와 함께 보여줄 수 있다.
- AI 추출 후보를 바로 원장에 넣지 않는 이유를 설명한다.
- 시계열 값은 별도 저장하고 장치·신호 ID로 연결한다.

전체 시스템 설계는 [기존 아키텍처 문서](../definition.md)를 함께 참고하십시오.
